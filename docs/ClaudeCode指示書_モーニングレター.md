# モーニングレター構築の指示書

あなた（Claude Code）に、暗号資産投資向けのモーニングレターを自動生成するツールの構築をお願いします。
既存の自作ツール **aion**（https://github.com/tjackiet/aion）をベースに、市場版を作ってください。

---

## 1. ゴール

毎朝 JST 7:00 以降に1コマンドを実行すると、次のものが手に入る状態にする。
- 株式・債券・為替・コモディティ・暗号資産の数値
- 今後30日の予定
- 主要ニュース

これらを集約し、「暗号資産投資の判断に役立つ」Markdown のレポートを出力する。
メイン銘柄は BTC。

## 2. 大原則（必ず守ること）

1. **数値は API から機械的に取得し、LLM に数値を作らせない。** Claude API の役割は、要約・判定理由・まとめの文章だけにする。LLM に渡すのは計算済みの数値に限る。
2. **株・指数・ETF の騰落率は、必ず日足 `history(interval="1d")` の終値から計算する。** `info` の `currentPrice` 系の項目は使わない。JST 7:00 は米国の時間外取引の最中なので、時間外の値が混ざるのを防ぐため。
3. **一部の取得に失敗しても、レポート全体は止めない。** 該当欄は「取得失敗」と表示し、ログに理由を残す。
4. **設定は YAML に寄せる。** 銘柄・フィード・キーワード・イベントを、コードを触らずに変更できるようにする。
5. **テストはネットワークに依存させない。** 実データから作った固定データ（fixtures）でテストする。aion の `tests/` の流儀に合わせること。
6. **時刻はすべて JST で表示する。** データごとの基準時刻（NY終値／取得時点）をヘッダーに明記する。

## 3. aion から流用するもの

| aion のモジュール | 流用方法 |
|---|---|
| `collector/rss.py` | そのまま流用し、フィードを市場向けに差し替える |
| `selector/`（絞り込み・スコアリング・ランキング） | そのまま流用し、`keywords.yaml` を市場用語に差し替える |
| `processor/summarizer.py` + `prompts.yaml` | 「Why it matters」を「暗号資産への示唆」に変更する |
| `reporter/markdown.py` | 新しい骨子に合わせて作り直す |
| `publisher/notion_mcp.py` | 残しておく（出力先は未決。後述） |

リポジトリは aion をベースに新規作成する。リポジトリ名は `good-morning`（`git@github.com:tjackiet/good-morning.git`、**公開リポジトリ**）。aion は `git@github.com:tjackiet/aion.git` から取得する。

### 公開リポジトリなので守ること
- `config/watchlist.yaml`、`outputs/`、`.env` は `.gitignore` に入れて push しない。
- コミットするのは `config/watchlist.example.yaml` と `.env.example` だけにする。
- `watchlist.yaml` がないときは、example を読み込んで警告を出す。
- **フェーズ0の最初のコミットより前に `.gitignore` を作ること**（一度 push したファイルは履歴に残るため）。

## 4. データ取得元

| 対象 | 取得元 | 備考 |
|---|---|---|
| 株・指数・為替・金利・商品・セクターETF | yfinance | 非公式ライブラリなので、取得処理は1か所にまとめ、差し替えやすくしておく |
| 暗号資産 | bitbank-lab-mcp（MCP Python SDK 経由。aion の Notion 連携と同じ方式） | 注意点は後述 |
| 経済指標の発表予定日 | FRED API の発表予定日（`fred/releases/dates`、`include_release_dates_with_no_data=true`） | APIキーは環境変数 `FRED_API_KEY` で渡す |
| FOMC・日銀会合 | `config/events.yaml` に公式日程を年1回手で転記する | FOMC議事要旨は会合の約3週間後に公開。日付も一緒に書く |
| 決算日 | yfinance `Ticker.calendar` / `get_earnings_dates()` | 確定／推定を区別する |
| ニュース | RSS（aion の仕組み） | |

### bitbank-lab-mcp の使い方の注意（重要）

検証で次の問題が分かっています。

- **文章のラベルを使わないこと。** 同じ出力の中で、RSI 37.0 が「中立圏」と「弱め（反発余地）」の両方で表示される。判定は、`structuredContent` の数値から自前の基準で行うこと。
- **週足・月足でも「200日」「5日前」「26日後」と表示される**（実際は「本」の意味）。数値だけを使い、単位はこちらで付けること。
- **`analyze_sma_snapshot` は月足では使えない**（必要本数が200本以上の制約があり、結果が n/a になる）。月足の移動平均は `analyze_indicators(type=1month)` の値を使う。月足の200本線はデータ不足のため「算出不可」と表示する。
- **最新の足は形成中。** 週足・月足が途中経過であることをレポートに一言入れる。
- **使うツール**
  - BTC のテクニカル：`analyze_indicators` を日足・週足・月足で各1回
  - ウォッチリストの価格：`get_tickers_jpy`
  - 取扱銘柄の確認：bitbank の取扱銘柄一覧
- 最初に `structuredContent` の中身を確認し、必要な数値（一目均衡表の各線、SMA 25/75/200、BBのσ位置、RSI(14) と直近7本、MACD）が取れることを確かめてから実装すること。取れない項目があれば、bitbank の公開API（ローソク足）から自前で計算する予備の処理を検討する。

## 5. レポートの骨子

0. **ヘッダー**：日付、データ基準時刻（NY終値／BTCは取得時点／先物は取得時点の値／週足・月足は形成中）
1. **今朝のまとめ**：「リスクオン／リスクオフ／様子見」の3段階判定と、3行の要約（Claude が生成。根拠となる数値を必ず挙げる）
2. **マーケット一覧**（表。終値・前日比・前日比%）
   - BTC/JPY（bitbank、24時間の変化率）
   - 米10年債利回り `^TNX`（%表示、前日比は bp）
   - ドル円 `JPY=X`
   - NYダウ `^DJI`、S&P500 `^GSPC`、ナスダック総合 `^IXIC`
   - WTI原油先物 `CL=F`、金先物 `GC=F`
   - 任意（設定でオン・オフ。初期値はオン）：VIX `^VIX`、ドルインデックス `DX-Y.NYB`、株価指数先物 `ES=F` `NQ=F` `YM=F`
3. **セクター別騰落率**：SPDR 11セクター（XLK, XLF, XLE, XLV, XLY, XLP, XLI, XLB, XLU, XLRE, XLC）を騰落率順に並べる（Markdown の表。グラフは不要）
4. **BTCの詳細**：下の表と、日足RSIの直近7日の推移、Claude による2〜3行のまとめ

   | | 日足 | 週足 | 月足 |
   |---|---|---|---|
   | 一目：雲との位置 | | | |
   | 一目：三役 | | | |
   | 移動平均の並び（25/75/200本） | | | |
   | ボリンジャーバンドのσ位置 | | | |
   | RSI(14) | | | |
   | MACD | | | |
   | 判定 | | | |

   **判定のルール**：5つの要素（雲との位置、三役、移動平均の並び、RSI、MACD）を強気+1、弱気−1、中立0で点数化する。合計が+2以上なら「強気」、−2以下なら「弱気」、それ以外は「中立」。
   **RSIの区分**：30以下は売られすぎ、30〜45は弱め、45〜55は中立、55〜70は強め、70以上は買われすぎ。
   区切りの値はすべて YAML で変更できるようにする。
5. **暗号資産ウォッチリスト**（5銘柄）：価格、24時間の変化率、対BTCの強弱（BTCの変化率との差）
6. **株式ウォッチリスト**（米国株10銘柄）：終値、前日比、騰落率順
7. **今後の予定**（決算と経済イベントを日付順にまとめる）
   - 7日以内：日時（JST）、内容、重要度（高・中・低）、予想値（取れれば）
   - 8〜30日：1行ずつの簡易一覧
   - 決算の対象：ウォッチリストの銘柄と、`related` に書いた関連企業
8. **主要ニュース**（3〜5本）：見出し、2〜3行の要約、暗号資産への示唆、出典リンク
9. **暗号資産への示唆**：強気材料、弱気材料、まとめ1〜2行
- **フッター**：投資助言ではない旨、データの出典

## 6. 設定ファイル

`config/watchlist.example.yaml`（銘柄は仮。ユーザーは手元でこれを `watchlist.yaml` にコピーして使う）

```yaml
crypto:
  main: btc_jpy
  watch: [eth_jpy, xrp_jpy, sol_jpy, doge_jpy, link_jpy]   # 最大5
stocks:                                                     # 最大10、米国株のみ
  - ticker: NVDA
    name: エヌビディア
    related: [TSM, AMD, AVGO, SMCI]
  - ticker: COIN
    name: コインベース
    related: [HOOD, MSTR]
  - ticker: MSTR
    name: ストラテジー
    related: []
```

- 暗号資産のペアは bitbank の取扱銘柄と照合する。存在しないペアは警告してスキップする。
- 上限を超えたら、先頭から順に採用する。

その他の設定ファイル：
- `config/markets.yaml`：マーケット一覧とセクターの銘柄コード、任意項目のオン・オフ
- `config/events.yaml`：FOMC と日銀の日程、重要度
- `config/feeds.yaml` / `config/keywords.yaml`：市場ニュース向けにする（下記）
- `config/scoring.yaml`：判定ルールの区切りの値

### ニュースのフィード（初期案。RSS の URL が実際に生きているかを確認し、死んでいるものは除外して報告すること）
- 暗号資産：CoinDesk、CoinPost、Cointelegraph（日本語版）、The Block
- マクロ・市場：ロイター（ビジネス・マーケット）、日経のマーケット系、Bloomberg の公開RSS（あれば）
- 公的機関：FRB のプレスリリース、日銀の新着、SEC のプレスリリース

### キーワードの初期案
FOMC、利上げ、利下げ、CPI、PCE、雇用統計、米国債、利回り、ドル円、日銀、ETF、SEC、ステーブルコイン、規制、ビットコイン、イーサリアム、半減期、清算、ハッキング、マイクロストラテジー、ブラックロック、関税、地政学

## 7. 進め方（フェーズに分ける）

各フェーズの最後に、次の3つを行ってから止まり、ユーザーの確認を待つこと。
- テストを通す
- 実データで1回動かす
- 出力のサンプルを見せる

| フェーズ | 内容 |
|---|---|
| 0 | リポジトリの準備（aion の複製、AI専用部分の整理、`CLAUDE.md` に本指示書の要点を記載） |
| 1 | yfinance でマーケット一覧・セクター・株式ウォッチリストを取得し、Markdown の表を出す |
| 2 | bitbank-lab-mcp に接続し、BTCの詳細（判定ルールを含む）と暗号資産ウォッチリストを作る |
| 3 | 今後の予定（決算・FRED・events.yaml）を作る |
| 4 | ニュース（RSS の差し替え、要約プロンプトの変更）を作る |
| 5 | Claude による「今朝のまとめ」「暗号資産への示唆」を作り、全体を結合して `outputs/YYYY-MM-DD.md` に出力する |
| 6 | 定時実行の設定（macOS の launchd で、平日・土日とも JST 7:15 に実行。夏時間・冬時間の切り替えでも 7:00 以降なら影響なし） |

## 8. 未決事項（初期値で進め、変更しやすくしておく）

- **出力先**：まずはローカルの Markdown のみ。Notion への書き出しは aion の機能を残し、オプションにする。
- **ウォッチリストの銘柄**：上記は仮のもの。
- **任意項目**（VIX、ドルインデックス、株価指数先物）：初期値はオン。

## 9. 環境変数

- `ANTHROPIC_API_KEY`（要約・まとめ用。モデルは aion と同じ設定に合わせる）
- `FRED_API_KEY`
- bitbank-lab-mcp は公開データだけを使うので、APIキーは不要（private 系のツールは使わない）
